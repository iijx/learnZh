# 识字大纲总体规划（Syllabus v1）

> 目标用户：零基础识字的中老年人
> 终极目标：让不识字的人达到**功能性阅读**——自由阅读日常生活文本与浅易书面语
> 本文档是"学什么"的总纲，所有字表、场景课、古诗故事、音频生产以本文档为准。

---

## 1. 目标量化：到底要学多少字

"认识每一个字"需要翻译成可验收的数字。汉字数量与学习收益的关系：

| 识字量 | 一般书面文本覆盖率 | 大致相当于 |
|---|---|---|
| 500 | ~78% | 当前版本目标（太少） |
| 1000 | ~89% | 小学一年级上 |
| 1500 | ~95% | **国家成人脱盲标准** |
| 2000 | ~97% | 小学二年级 |
| **2500** | **~99%** | 自由阅读报刊、微信文章 |
| 3500 | ~99.5% | 《通用规范汉字表》一级字，边际收益极低 |

**结论：总目标定为 2500 字。** 这是"功能性阅读"的甜点：再往上每多学 500 字，覆盖率只提升约 0.3%，但学习周期增加 3 个多月，对老年学员不划算。3500 字以后剩下的主要是人名地名生僻字，遇到时教"问子女/拍照问"的策略即可，不进入课程。

参照系：成人扫盲 1500 字；义务教育语文课标小学毕业累计认识 3000；洪恩识字 1300；悟空识字 1200。

## 2. 五级大纲

2500 字分五级，每级有明确的**能力承诺**（学完能读懂什么），级别即里程碑：

| 级别 | 名称 | 新增 | 累计 | 周期@5字/天 | 能力承诺（可验收） |
|---|---|---|---|---|---|
| L1 | 生存篇 | 300 | 300 | ~2 个月 | 看懂价签、药盒剂量、公交站牌、钱数、日期 |
| L2 | 生活篇 | 500 | 800 | +3.5 个月 | 读懂手机短信、小区通知、菜单、快递信息 |
| L3 | 脱盲篇 | 700 | 1500 | +4.5 个月 | 读小故事、浅近古诗、说明书全文——**达到国家脱盲标准** |
| L4 | 报刊篇 | 500 | 2000 | +3.5 个月 | 读报纸标题、微信文章大意、天气预报 |
| L5 | 自由篇 | 500 | 2500 | +3.5 个月 | 自由阅读一般书面语（99% 覆盖），毕业 |

- 全程约 **17 个月**（每日 5 字）。设置页已有每日 1/3/5 字选项，周期相应缩放（每日 3 字约 28 个月）。
- 每级结业是一个大庆功节点（奖状 + 语音报喜 + 子女通知），级别之间不设门槛考试，自然衔接。
- L3 结束（1500 字）是最重要的对外传播点："我妈脱盲了"。

### 每级内部：单元制

- 每 **25 字 = 1 个单元**（5 天 × 5 字），每个单元围绕 **1 个生活场景主题**组织选字。
- 单元第 6 天不上新字，上该主题的**场景课**——场景课就是单元毕业考。
- 由此场景课的解锁机制从"每 25 字自动解锁"升级为"**与单元绑定**"，从根上消除当前"字表顺序与场景用字脱节"的问题（scene.js 的兜底逻辑可删除）。

## 3. 选字方法论：语料倒推 + 权威表校准

旧字表（现代汉语书面字频 + 主题拼凑）废弃。新字表按四步生成：

### 第 1 步：建目标语料库（权重 60%）

先写"要读懂的东西"，再统计"需要哪些字"：

- 60 个生活场景的完整文本（价签、药盒、说明书、站牌、叫号屏、取款机、短信、通知栏、菜单、快递单、火车票、天气预报、挂历……）——**初稿已完成：`content-pipeline/corpus/scenes.json`（60 场景 / 770 个独立汉字），统计工具 `corpus/stats.js`**
- 30 首浅近古诗、30 篇生活小故事
- 真实样本：报纸标题 500 条、微信公众号文章 50 篇、社区通知 50 份

对语料做单字频率统计，得到**生活字频表**——这是本产品的核心资产，通用字频表里没有"药盒上出现频率"这个维度。

### 第 2 步：权威表校准（权重 40%）

生活语料覆盖不全的（虚词、结构字），从权威来源补齐：

- 《通用规范汉字表》一级 3500 字（界定"常用"的边界）
- 小学语文一、二年级教材识字表（已经被教学验证过的难度排序）
- 现代汉语通用字频表（补 `的地得了着过在是有` 这类功能字）

### 第 3 步：双维打分、分级归单元

每个字按 **场景急需度 × 通用频率** 打分排序，再按级别容量切分；级别内部按单元主题聚类（见 §5 L1 示例）。每个字入库时必须绑定**首次应用场景**（sceneId）——字不离词、词不离句、句不离境。

### 第 4 步：校验（见 §6）

## 4. 字表数据结构变更

字序真相源为 `content-pipeline/syllabus.json`（**已落地**）：`levels` 定义五级元信息，`order[]` 记录每个字的归属：

```js
{ char: '药', level: 1, unit: 3, sceneId: 3 }
```

`apply` 写回 `data/chars.js` 时按此顺序排序；`publish` 按 level 拆包下发，包内每条字文案附带 `unit` 字段：

```js
{
  char: '药',
  pinyin: 'yào',
  unit: 3,           // 级别内单元号（包内下发）
  explain: '...',    // 大白话讲解（不变）
  mnemonic: '...',   // 记字诀（不变）
  words: ['吃药', '药店', '中药'],
  sentence: '这药一天吃两次。',
  hasStroke: true
}
```

CDN 课程包方案已实现：字表按 level 分包（`learn-zh/chars.L1.json`，L1 已上线，见 `course-package.md`），小程序按需加载，避免 2500 字全量塞进包体。

## 6. 质量验收规则（脚本化，纳入 tools/）

任何一级上线前，必须跑通 `tools/check-syllabus.js`：

1. **无重复**：字表内 char 唯一（当前版本 `家` 重复，501≠500，须修复）。
2. **场景课自洽**：每节场景课的 `items` 用字 ⊆ 该单元及之前已学的字。
3. **文本 i+1**：古诗/故事/文章的生字率 ≤ 5%，且单篇生字 ≤ 2 个（生字配即时讲解）。
4. **内容完整度**：上线字必须七件齐全——拼音、讲解、记字诀、3 组词、1 例句、音频、笔顺。缺一不上线（不再允许"内容待补充"占位进入用户可见范围）。
5. **覆盖抽测**：每级用 20 篇未参与选字的真实生活文本抽测，验证"学完 Lx 能读懂"的承诺，生字率超标则回头修字表。

## 7. 内容生产管线与成本

| 资产 | 总量 | 生产方式 | 备注 |
|---|---|---|---|
| 字讲解文案 | 2500 字 × 4 件 | LLM 按模板批量生成 → **人工审校**（已实现：`content-pipeline/`） | 模板要求：大白话、禁书面语、例句限 15 字内 |
| 笔顺数据 | 2500 字 | **开源数据全量获取**（npm `hanzi-writer-data`，覆盖 9575 字），`publish` 自动生成 `strokes/<字>.json` 上 CDN（已实现：`content-pipeline/lib/strokes.js`） | 免费，`hasStroke` 可达 100%（L1 已 300/300） |
| 音频 | ~1.5 万条 + 讲解/里程碑 | 现有 audio-pipeline（豆包 TTS → 腾讯云 COS）直接复用 | 每字 7 条：字音、讲解、3 词、例句；里程碑童谣/故事逐行 |
| 场景课 | 60 节 | 场景图 AI 插画 + 人工标注文字热区 | L1 12 节 / L2 20 节 / L3 16 节 / L4 8 节 / L5 4 节 |
| 古诗 | 30 首 | L1 用原创童谣（经典古诗低级别生字率必然超标）；L3 起按级别生字率引入浅近古诗 | L1 六首已上线（生字率 0） |
| 故事 | 30 篇 | 原创 50-80 字生活故事，i+1 原则 | 每篇生字 ≤ 2；L1 三篇已上线 |
| 报刊/文章 | L4 起 | 真实报纸标题、公众号段落改写 | 配朗读与点读 |

**审校是主要人力成本**：2500 字文案按每人每天审 100 字计，约 25 人天，建议分级随做随审，不攒到最后。

## 10. 一句话总结

**2500 字、五级、单元制：从"要读懂的文本"倒推字表，每 25 字一个场景单元，学完即有可验收的阅读能力。** 流程机制（复习、描红、场景课）全部复用现有代码，这次规划只动"内容与结构"，不动"引擎"。
